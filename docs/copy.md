# Site copy

Read this before writing or changing any text that appears on the site.

Copy is part of the work, not filler around it. It addresses the reader informally
(German "Du"). The rules below are the ones that kept being broken:

- **Plain German, no agency copy.** "Frist im Nacken", "auf dem Tisch", "ungutes Gefühl" —
  all cut. The audience is a bank or an insurer; anything that sounds like a campaign
  undermines the sober tone of everything else.
- **No vague slogans.** "Lösungen statt Listen" and "Design von Anfang an" were cut.
- **No cocky first person.** "Ich finde es …" states an opinion. Say what happens instead.
  Not robotic either: it should read like a person talking.
- **Phrase it positively.** "Keine Lust auf Felder?" starts from the negative.
- **Correct German.** "Mehr dazu im Datenschutz" is wrong; "Mehr dazu in der
  Datenschutzerklärung" is right.
- **Short imperative forms, as people speak.** "Drück", "Erzähl", "Schreib", not
  "Drücke", "Erzähle", "Schreibe". Where the short form sounds wrong, the long one stays
  ("Ergänze").
- **Friendly, clear error messages**, without control terms that do not fit everyone, such
  as "Haken raus".
- **Mark an example as an example.** "Jedes Projekt ist anders" tells the reader the
  process shown is one possibility.
- **Say what happens.** A button reads "Projekt anfragen", not "Anwendung schildern". A
  label that needs interpreting is wrong.
- **Fixed wording for the inquiry.** Never "Vorhaben"; the page asks "Worum geht es?" and
  says "Dein Projekt". The first call is "unverbindlich und kostenlos", never only
  "kostenlos".
- **Read every sentence for what it literally claims.** "Deshalb landen die Fehler in der
  Anwendung" says the author puts bugs into the product. Grammar that parses is not the
  same as a sentence that means the intended thing.
- **No invented numbers.** "Tools find about a third of the issues" was cut because it
  could not be sourced. Either it is verifiable or it does not appear.
- **Terminology has to be right.** WCAG has success criteria, not paragraphs. EN 301 549
  V4.1.1 (published September 2026) references WCAG 2.2, and that is what this project
  tests against. Until it is cited in the EU Official Journal, the older version citing
  WCAG 2.1 is the one that legally grants presumption of conformity. A wrong term
  on an accessibility page costs more than a missing sentence.
- **An empty state says that nothing has happened yet.** A placeholder announcement such as
  "Bereit. Drück Weiter" reads like an error.
- **No invented screen reader captions.** Check what the element really is first. The
  process steps are an ordered list, so they get no caption.
- **Say a thing once.** The same argument in two sections reads as padding.
- **Text before layout.** Write the copy, then build the element around it — never fill a
  layout with words afterwards.
